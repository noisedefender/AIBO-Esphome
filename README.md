# ESPHome: головка песочного фильтра бассейна (Aibo / Likebo, 6 позиций)

Управление фильтровальной головкой по **RS485 (Modbus RTU, unit id 1)** с ESP32-S3 и Home Assistant:
выбор из 6 режимов, давление, порог промывки по давлению, синхронизация часов головки.

Файл: [`pool-filter.yaml`](pool-filter.yaml).

## Что умеет

| Сущность в HA | Регистр | Тип |
|---|---|---|
| `Pool filter mode` (select) | `0x0014` | запись, 1..6 |
| `Pool filter position (1-6)` (sensor) | `0x0013` | чтение, 1..6 |
| `Pool filter pressure` (sensor, kPa) | `0x0018` | чтение |
| `Backwash pressure trigger` (number, kPa) | `0x0017` | запись, 0..230 |
| `Filter head online` (binary sensor) | — | головка отвечает по Modbus |
| `Sync filter head clock` (button) | `0x0020..0x0022` | запись времени |

Режимы головки: `Filter`, `Backwash`, `Bottom pipe flushing`, `No filter drainage`,
`No filter cycle`, `Closed` (значения 1..6).

## Пробуждение (wake)

Головка спит и не отвечает на чтение, пока её не разбудят. Wake — это запись регистра `0x0004`
значением 10 (magic пакет из вендорного приложения):

```
01 06 00 04 00 0A 48 0C
```

В этом конфиге wake отправляется автоматически и всегда раньше команды:

- перед записью режима и уставки — через `write_lambda` (wake встаёт в очередь хаба до кадра записи);
- перед опросом — `interval` на 1 секунду короче `update_interval` (`wake_interval: 59s`, `poll_interval: 60s`).

То есть головка фактически поддерживается в бодрствующем состоянии. Если хотите «только перед
командами», увеличьте `poll_interval` и уберите блок `interval`.

## Подключение

- RS485-трансивер (MAX485 / SP3485 / готовый RS485-модуль) к ESP32-S3:
  - `TX` → пин `rs485_tx_pin` (по умолчанию GPIO8), `RX` → пин `rs485_rx_pin` (GPIO9);
  - `A`/`B` — к A/B головки, общий провод/земля — к GND ESP32;
  - пин направления (DIR/RE-DE) не нужен: в проверенной конфигурации направление переключается
    автоматически, `flow_control_pin` не используется.
- 8N1, `baud_rate: 19200`. Если у вас другой мост — поменяйте substitution `rs485_baud`.
- От вендорной головки идёт ещё Wi-Fi мост (`10.10.100.254:15000`, тот же Modbus RTU) — этот конфиг
  его не использует, работает напрямую по проводам.

## Установка

1. Понадобится **ESPHome 2026.x** (нужны действия `modbus_client.write_single_register` /
   `write_multiple_registers`). Для более старых версий замените кнопку часов на `write_lambda`
   с `item->write_multiple_registers(...)` или на три `number`-сущности (`0x0020..0x0022`).
2. Создайте `secrets.yaml`:

   ```yaml
   wifi_ssid: "your-ssid"
   wifi_password: "your-password"
   api_key: "<32-байтный base64 ключ, сгенерирует esphome run>"
   ```

3. `esphome run pool-filter.yaml` (или через аддон ESPHome в HA).
4. В Home Assistant устройство появится само; сущности `select` / `number` доступны сразу.

## Настройки (substitutions в начале файла)

| Substitution | По умолчанию | Значение |
|---|---|---|
| `rs485_tx_pin`, `rs485_rx_pin` | 8, 9 | пины трансивера |
| `rs485_baud` | 19200 | скорость RS485 |
| `poll_interval` | 60s | как часто читать регистры |
| `wake_interval` | 59s | как часто будить (должен быть на 1 с меньше `poll_interval`) |
| `trigger_min`, `trigger_max` | 0, 230 | диапазон уставки давления, кПа |

## Карта регистров (unit id 1, Modbus RTU, CRC-16 Modbus, младший байт CRC первым)

| Регистр | Смысл | Кадр |
|---|---|---|
| `0x0004` | пробуждение | `01 06 00 04 00 0A 48 0C` |
| `0x0013` | текущая позиция (1..6) | `01 03 00 13 00 01 75 CF` |
| `0x0014` | позиция (запись) | `01 06 00 14 00 01 08 0E` (Filter), `… 00 02 48 0F` (Backwash), `… 00 03 89 CF` (Bottom pipe flushing), `… 00 04 C8 0D` (No filter drainage), `… 00 05 09 CD` (No filter cycle), `… 00 06 49 CC` (Closed) |
| `0x0017` | порог промывки по давлению, кПа | `01 06 00 17 00 5C 39 F7` (92 кПа) |
| `0x0018` | давление, кПа (шкала 0..350) | `01 03 00 18 00 01 04 0D` |
| `0x0020..0x0022` | часы головки (FC 16: год/месяц, день/час, минута/секунда) | `01 10 00 20 00 03 06 1A 0B 16 14 05 22 87 14` |

Значения в регистрах — целые числа: 92 кПа пишется как `00 5C`, 30 секунд как `00 1E`.

### Что не реализовано

Расписание промывки по времени (задачи 1..3 и авто-включение/выключение) сознательно не добавлено:
`0x0023` (запуск задачи), `0x0024..0x0029` (расписания), `0x0030..0x0038` (длительности промывки /
промывания / второй промывки), `0x0039` + `0x003A..0x003D` (auto on/off по расписанию).
Эти регистры writes те же (FC 06 / FC 16), так что их легко добавить `number`/`switch`-сущностями.

## Диагностика

Кадры для сканирования карты регистров (после wake):

```
01 03 00 00 00 0A C5 CD   # регистры 0..9
01 03 00 0A 00 0A E5 CF   # 10..19
01 03 00 14 00 0C 05 CB   # 20..31
01 03 00 20 00 10 45 CC   # 32..47
```

Ответ имеет вид `01 03 <byte_count> <значения> <crc_lo> <crc_hi>`.

Если `select` ругается в логе («No option found for mapping»), значит головка не возвращает
`0x0014` при чтении: ориентируйтесь на sensor `Pool filter position (1-6)` (регистр `0x0013`),
`optimistic: true` делает состояние `select` локальным.

## Безопасность

Промывка и слив реально переключают поток воды через фильтровальную установку и могут
опорожнять бассейн. Не включайте автоматизацию режима по расписанию без проверки: сначала
управляйте вручную и убедитесь, что конкретная головка корректно отрабатывает каждый режим.
